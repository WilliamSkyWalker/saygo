# Saygo 0.4.20：补齐 Python 包中的插件文件

0.4.19 已发布到 PyPI，包含 Android 人工接管键盘修复。随后核查发现其源码分发包
遗漏三个插件文件，从该源码包构建的 wheel 内嵌安装资源也因此不完整。
本版补齐打包清单和完整性检查，并升级版本元数据；不改动 0.4.19 的输入法、
Runtime 或性能实现。本轮发布范围仍为 PyPI Python 包。

## 修复内容

补入 `plugins/saygo-device/` 下的三个现有文件：

- `scripts/doctor.py`：插件 doctor 命令实际调用的诊断脚本。
- `scripts/saygo_mcp.py`：插件提供的 MCP 启动辅助脚本。
- `LICENSE`：随插件分发的许可文件。

打包检查须覆盖源码分发包、由源码分发包构建的 wheel、wheel 中的
`_setup_source.zip`，以及首次和重复 setup 生成的插件副本，避免仅检查源码
目录存在就判断分发完整。0.4.19 的主 CLI/MCP 输入法修复已经包含在公开包中，
本问题不等于这些修复丢失或所有 MCP 入口无法启动。

## 升级与迁移

0.4.20 已发布到 PyPI，按原方式升级，例如：

```sh
pipx upgrade saygo-agent-control
```

若已使用缺文件的包执行过 setup，升级后对原客户端再执行一次 setup，以补齐
已复制的托管插件文件；例如原客户端为 Codex 时使用 `saygo setup --client codex`。
保留原安装使用的客户端、`--root` 等选项，然后重启该客户端加载更新。
无需迁移任务数据库或清空设备状态，也不要通过修改 site-packages 修补已发布包。

本轮没有直接升级用户安装环境。收尾只读复核时本地运行时已为 0.4.19，
输入修复文件与公开包一致；尚未安装 0.4.20，也未确认正在运行的客户端已
重新加载代码。发布包不会主动重载扩展或关闭在线 host；本轮不创建 GitHub
公开 Release、不发布新桌面包，也不向扩展商店上传。

## 验证与边界

0.4.20 完整 CI 已通过：核心 1,043 通过、7 跳过；真实扩展 4 项和 Playwright
1 项通过。构建源码白名单、三平台干净安装、实际插件 doctor 诊断和重复
setup 均通过。PyPI 两份公开产物未撤回，下载哈希与 CI 一致；公开 wheel
在隔离 Linux 环境再次验收通过。详情见
[0.4.20 发布验证](history/release-0.4.20.md)。

Android 人工输入证据来自 [0.4.19 源码验收](../android/handoff-validation.md)：
独立模拟器上分别通过普通 device 和真实 MCP Runtime 验证软键盘、电脑键盘、
接管后恢复自动中英文输入、重复接管及暂停态重连。本轮只修分发文件，不将
这份历史证据表述为 0.4.20 重新执行了真实 Android 验收。iOS 仍只有离线契约
覆盖，没有本次真机或 Simulator 人工输入验收。
