# Saygo 1.0.1：局部画面变化保护与升级选择

本次仅发布 Python runtime 和随包分发的客户端插件，版本为 1.0.1。
浏览器扩展保持 1.0.0，协议保持不变；不提交新的商店版本或构建原生桌面包。
发布准备、验证和公开索引核对见 [1.0.1 记录](history/release-1.0.1.md)。

## 行为变化

- 浏览器单点操作可容忍当前观察采样过、远离目标的小范围画面再次出现。
  比较在本地进行，仅保留本次等待的最后最多四帧；不做跨观察学习，不把中间帧交给模型。
  身份、URL、尺寸、目标上下文、新内容和大范围变化仍受保护。
  未采到对应画面或证据缺失时继续拒绝；输入、按键和滑动不使用此例外。
- 普通 device 画面拒绝返回 `not_dispatched`、`requires_observation: true`，
  尽可能附上实际比较帧与变化边界。等待后的观察复用末帧和真实采集时间，
  日志复用同一观察；拒绝与未知结果均不自动重放。
- MCP 确认有新版后，在新输入前要求用户选择升级或本次继续。
  继续仅适用于当前 MCP 进程；升级保持输入暂停并提供说明，不自动执行安装。
  观察、诊断、人工核对和取消仍可用，历史请求去重查询先于升级检查。
- 本进程首次使用异步刷新版本，避免近期旧缓存遗漏新版本；后续复用缓存。
  无已知新版的离线检查不阻断输入，已知新版在暂时检查失败时继续保留。

## 升级与验证边界

包模式使用 `pipx upgrade saygo-agent-control`，并重启 Agent 客户端加载新代码。
复制式插件还需按原客户端与目录重新 setup，以取得更新后的操作 Skill。
已有会话、观察与请求记录无需迁移；旧观察没有局部采样证据时继续采用原保护。
发布不修改用户安装、不重载扩展、不结束在线 native host。

本次离线回归、构建及干净安装结果分别记入版本记录。当前环境中，修改前后的
MCP stdio 初始化均超时，不能记为通过；真实浏览器因测试依赖缺失未执行本次验收。
发布工作流按既有约定只构建和上传，工作流成功不代表端到端测试通过。
