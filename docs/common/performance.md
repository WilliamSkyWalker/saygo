# 性能实现、测量与计划

[公共文档](README.md) · [QA 需求](requirements.md#qa) · [QA 操作](qa.md)

性能目标是减少重复计算、实际耗时、模型调用和慢加载导致的假失败，不能用降低断言质量换速度。局部计算基准与完整 QA 业务基准分别记录，历史基准不代表本次重新测量。

## 当前实现

| 能力 | 当前行为 | 限制 |
| --- | --- | --- |
| 稳定帧检测（阶段 1） | settle 使用像素差、状态栏遮罩、稳定帧数和超时；不调用大模型 | 尚未在 settle 内集成加载检测、OCR 或模板匹配 |
| 多帧断言（阶段 1） | 操作用末帧；断言取窗口首/中/末帧，任一帧对变化 ≥2% 时保留三帧，否则只用末帧 | 不足三帧时只用末帧；不能保证抓到每个短暂提示；AGENT_ASSERT_BURST_FRAMES=3 是回退采样 |
| 等待预算（阶段 2） | AGENT_WAIT_MAX_S 默认 45 秒，为每步累计主动等待预算；预算内 wait 不计无进展，耗尽后恢复计数 | 仍由模型复查目标是否出现，未实现“只在预筛命中后调用一次模型” |
| 同屏断言合并（阶段 3） | AGENT_MERGE_ASSERTS 默认开启，同步返回每条 verdict/evidence/where；整块有效通过才推进 | probe 不参与合并，文本证据检查不等于独立验证图像 |
| 现场弹窗处理（阶段 3） | 失败时可检测拦截弹窗、关闭、重新截图重判，最多两次 | 设备仍在现场才有效；不是任意应用自动修复 |
| 可选元素定位 | 配置 Locator 且 tap/long_press 有 target 时先定位，失败沿用 Brain 坐标 | 旧 no_effect 像素差检测及对应重试触发已停用 |
| 批量操作（阶段 5） | AGENT_SPLIT_ACT_CHECK 默认关闭；开启时 Brain 拆序列，Locator 按需定位，批量后 Brain 核验；连续两次失败回退 | 不是零大模型调用，像素差不能证明操作成功 |

实现位置为 saygo/vision/settle.py、saygo/qa/agent.py、brain.py、step_validator.py、saygo/config.py。默认禁用子动作和场景总轮数上限，主要在 15 个计数轮次未推进时收敛；预算内等待和 probe 轮询除外。普通步骤索引必须等于当前步骤，合并断言使用独立校验器，不放宽普通规则。

## 局部计算基准（2026-10-13）

本轮重构集中在三处重复工作：qa.cases 共享目标归属解析并避免绝对目录扫描两次；settle 复用已预处理的帧，visual_diff 用直方图统计并在零变化时跳过区域分析；Runtime 查询事件时不解析完整快照，导出只读一次历史。CLI/MCP 参数、数据库和导出格式保持兼容，无需迁移。

使用 [benchmark_core_paths.py](../../scripts/benchmark_core_paths.py)，在 Linux x86_64 / WSL2、Python 3.12.3、Pillow 12.3.0 上比较基线 `4ef5c2a` 与本轮工作区。每项预热一次，再执行九次取中位数，单位为毫秒：

| 路径 | 基线 | 重构后 |
| --- | ---: | ---: |
| Markdown 目录发现 | 5.653 | 2.684 |
| 静态三帧采样 | 156.036 | 69.837 |
| 动态三帧采样 | 151.375 | 67.282 |
| 零变化视觉差异 | 583.062 | 16.252 |
| 动态视觉差异 | 546.128 | 496.040 |
| 事件历史读取 | 9.718 | 4.271 |
| 任务 ZIP 导出 | 67.164 | 53.889 |

目录负载为 300 个空子目录，加 cases 目录中的一个 Markdown 用例，没有 feature。图像为 1080×1920 的 RGB 合成 PNG，静态为相同画面，动态为背景变化；原始截图、变化阈值、区域和采样选择保持一致。Runtime 使用约 4.1 MB 的合成快照、2,002 条事件，导出不含截图附件。

复测时用同一份脚本、解释器与依赖，`--source` 指向要比较的源码检出目录：

```sh
python3 scripts/benchmark_core_paths.py --source /path/to/baseline-checkout --repeat 9
python3 scripts/benchmark_core_paths.py --repeat 9
```

所有数据均生成在临时目录中，脚本不连接设备或模型。结果反映这些计算/IO 路径，受主机负载与文件缓存影响；设备截图、固定轮询等待、模型时延和完整业务通过率未在此基准中测量。特别是动态视觉差异仍需膨胀与区域扫描，收益小于零变化画面。

## 已实现的断言约束

1. 每条独立返回 ID、结果、至少 15 字符并引用自身元素的证据，以及坐标/区域。缺字段拒绝整块。
2. 逐条禁止以假设、推断或后台逻辑冒充屏幕证据，连续三次无效响应判失败。
3. 跨断言检查雷同/模板化证据；负向断言必须说明检查区域及未发现对象，不能默认不存在。
4. 不可视断言使用 probe 或判未验证/失败，不因合并而跳过。
5. 同步保留现场重判机会；完成验证后才能离开当前页面。

原记录中四条同屏断言由四轮模型合为一次，并逐条保留证据；离线测试覆盖全通过、无弹窗失败、关闭弹窗后通过、持续弹窗两次后失败。该记录不是所有用例或本次测试的通过证明。

## 后续设计：尚未完成

- 加载/目标预筛：在固定间隔截图后用 loading_detector、OCR 或模板判断“可能出现”，再由模型确认，减少重复模型调用。自然语言目标提取、用例 timeout 和 wait_for 接口仍为设计。
- 确定性交叉核验：文字断言在同图 OCR 查对应文字，与模型结果比较，不能只相信模型表述。
- 弱证据复核：对最弱的 1–2 条断言独立发起反证检查；可先仅合并结构类断言，关键/负向断言独立验证。此方案不表示当前已按此分流。
- 更完整的动态采样：当前已取首/中/末帧并按 2% 变化分流；后续可评估最大变化点前后帧，比较短暂提示的漏检率。

阶段依赖为先测量，再改稳定帧/采样，其上改等待和断言；配置实验可独立对照。wait_settled 已是内部实现，wait_for 仍为设计，均不作为新增公开 API 承诺。

## 已否决：异步离屏断言

阶段 4 曾计划冻结断言帧、让设备立即进入下一用例，再异步裁决。该方案已否决，不在后续排期：结果回来时设备已离开现场，无法识别/关闭拦截弹窗并重截图，容易制造假失败。保留阶段 3 的同步合并。

## 历史基准与配置实验

原始基准为含 25 个场景的聊天类用例，三台 Android 真机：实际耗时 30 分 48 秒、聚合耗时 76 分钟、通过率 60%。主要耗时是等待应用自身 AI 回复、失败场景耗尽 15 轮无进展预算（当时约四分钟/场景），以及逐动作调用模型。基准当时 Locator 已启用，不能据此假定所有安装默认使用定位模型。

对照必须同一用例、同三台设备，同时量实际耗时、聚合耗时、模型调用和通过率：

- Locator 开/关：原实验候选 bytedance/ui-tars-1.5-7b；关闭时由 Brain 估坐标。
- AGENT_SPLIT_ACT_CHECK 开/关：比较批量执行净收益和失败率。
- Planner 分级：原实验候选 google/gemini-2.5-flash-lite，视觉 Brain 的历史配置为 gemini-3.5-flash；这些是历史样例，不是当前最佳模型推荐。

原基准对新闻类内容曾有模型内容审查导致拒答/误判的限制，因此保留其对读屏模型的选择约束；仅输出坐标的 Locator 单独评估。不可将该基准条件泛化为所有模型的准确率结论。

任何阶段若提速但通过率下降，先排查原因，不能削弱逐条证据、观察有效性或现场重判来使结果好看。
