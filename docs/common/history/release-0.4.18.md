# 0.4.18 发布验证

用户于 2026-10-13 在 0.4.17 发布启动后明确要求“再升级一个版本，把前面这个问题修复”。本版保留完整网络正文修复；不会将已有会话或部分导出误报为业务成功或历史完整。

Python、托管安装器、native host、客户端插件和桌面使用 0.4.18。扩展代码与已提交 Chrome 商店的 0.4.17 相同，继续使用 0.4.17，避免重复提交相同代码；最终检查已确认审核通过。网络完整性修复须配套升级 host 与扩展；仓库发布不会主动重载用户扩展或关闭在线 host。

## 已验证的修复

- 移除字段 32 Ki 字符、事件数量、每页/全局字节数、关联请求数量和并发正文读取的固定上限。
- native host 的网络回执不再受 32 MiB 总量限制；跨帧保留完整 Unicode。
- HTTP 响应实时保存字节，缓存淘汰后仅用完整流恢复；不完整或无法访问时明确返回错误，不伪造历史。
- 真实 Linux Chrome 扩展 → native host → CLI 完整读取超过 33 MiB 响应，长度、SHA-256、中文/emoji 尾部一致，并验证大 POST 正文。
- 本版最终标签通过 961 项离线回归（另 7 项跳过）、49 项 Node、4 项真实扩展与 1 项 Playwright；三平台桌面各 45 项及冻结启动/握手/模拟 IPC 通过。
- Windows 某次桥接测试在错误回执之后立即读取诊断状态，遇到正常异步发布的短暂窗口；测试改为有界等待状态发布。修正后的本地桥接 17 项通过；产品代码不变。

## 原工作区合并后的补充修复

发布快照之后的并行改动已合入 `main`（`2be5d1d`）：清空采集时重置 `pending_bodies`，旧请求完成不再改动新采集的计数。新回归在已发布扩展代码上失败，修复后 51 项 Node、33 项 Python 桥接/网络测试通过；独立 Linux Chrome 完整正文测试再次通过（26.735 秒），包括 33 MiB 缓存淘汰恢复及 Unicode POST。

这项计数修复只在源码分支，**不在已经发布的 0.4.18 附件中**；它不改变已发布的正文保留与恢复逻辑。没有移动标签、覆盖 PyPI 文件或再次增加版本号。原工作区与发布提交的差异已逐项合并，原始改动保留备份。

不包含四端真机业务验收、真实模型完整业务任务、桌面签名/公证或 Intel macOS 安装包。采集只保存连接期间浏览器实际提供的数据，不补齐既有部分业务 CSV；记录仍在内存中，用户须自行导出并核对历史范围。
