# 被测系统业务知识库与 QA

**状态：设计草案，开发时间待定。**

Saygo 按被测系统接入其业务规范、权限矩阵、状态流转说明和操作手册。用例作者可以从规则生成有出处的测试场景。执行时，AI 可以根据当前角色、单据状态和步骤检索适用说明，决定接下来要观察或操作什么。

## 知识源与适用范围

首版建议选一个被测系统，接入一份版本化文档目录或一个只读知识库搜索接口。查询限定在该系统及调用者可访问的资料内；返回相关片段、文档与章节、修订版本及适用条件。运行前固定本次采用的修订，执行中需要补查时沿用该修订。知识源接入方式和检索实现留待选定实际资料后确定。

个人任务知识库记录过去的操作和结果，业务知识库提供系统设计者声明的规则。用例引用时标明来源类型。若历史操作成功却违反当前权限规范，这条经验可以提示回归风险，测试预期仍以适用的规范为依据。[个人通用 Agent 与任务知识库规划](PERSONAL_AGENT_PLAN.md)

## 从业务规则到运行报告

| 环节 | 设计行为 |
| --- | --- |
| 用例编写 | 提取角色、对象归属、前置状态、允许或禁止的动作，推导正例、反例与边界场景。每条业务预期保留规则出处。规则缺失或冲突且影响预期时，标记待确认项。 |
| 执行规划 | Planner 按用例取得相关规则。通用登录、恢复到首页等短说明继续使用目标的 `_preconditions.md`；具体业务分支按需检索。 |
| 步骤执行 | AI 将当前观察与规则的适用条件核对，在用例指定的角色和目标内选择操作。发现文档冲突或界面行为偏离预期时记录差异，保留原断言。 |
| 结果判定 | 报告关联两类材料：规则出处说明应当发生什么，运行证据说明实际发生了什么。可见结果引用界面证据，后端状态使用已声明的 probe 核验。 |

知识库给出用例意图和预期结果。回放选用图像或元素树定位时，两种模式使用同一规则版本与断言。[BDD QA](../docs/common/qa.md) · [非视觉断言](../docs/common/probes.md) · [AI 操作录制与双模式回放](ai-action-recording.md)

## 待验收场景

以“申请人可以提交自己的单据；只有具备审批权限且非申请人的用户可以审批待审批单据”为示例规则。

1. 从规则生成本人提交、本人审批被拒、其他有权限者审批成功三个场景。检查权限反例包含“操作者同时具有审批权限”的条件，以隔离单据归属对结果的影响。
2. 分别以图像与元素树模式执行本人审批的反例。操作手册即使提供切换审批人的方法，AI 也须保持原测试身份。规则只约束审批结果时，应允许按钮隐藏、禁用或提交后被拒等界面表现。
3. 若用例要求“单据仍待审批”，用相应界面状态或后端 probe 核验。报告应能追溯规则版本和该单据的实际状态，仅观察到拒绝提示不足以证明后端状态。
4. 让同一适用版本的两份资料对本人审批给出相反结论，检查作者能否看到双方出处和待确认项；执行既有用例时，检查报告是否保留原预期并标明冲突。
