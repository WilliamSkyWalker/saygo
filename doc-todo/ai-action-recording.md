# AI 操作录制与双模式回放

[排期功能](README.md) · [统一操作](../docs/common/operations.md) · [BDD QA](../docs/common/qa.md)

**状态：设计草案，开发排期与各端验收待定。**

首版只录制 AI 通过 Saygo 派发的操作。用户录制一次，在运行测试时选择图像识别或元素树识别。两种模式执行同一份脚本的动作、输入和预期结果。模式名暂拟为 `image` 和 `tree`，后者在 Web 上对应 DOM 模式。

## 录制一次操作

以“点击订单 A 这一行的详情按钮”为例。两行都可能有名为“详情”的按钮，目标需要同时标明订单和控件。

1. **派发前采集目标。** 将动作关联到当前会话、绑定页面或窗口，以及动作前的观察。如果 AI 的初始点击位置经过二次定位，用最终即将派发的位置命中控件。若页面在观察与采集之间已变化，重新观察定位。
2. **为同一步保存两种定位信息。** 图像定位保存“订单 A 这一行的详情按钮”等视觉描述，可附参考图。元素树定位保存可重新查询的条件，例如“订单 A 所在行内，名称为详情的按钮”。当场核验树条件能否唯一找回本次命中的控件。若自绘区域只暴露整个画布，将该步标为仅支持图像定位，并记录原因。
3. **关联实际执行结果。** 将定位信息与派发记录对应。定位修正、被拒绝的候选动作或派发结果待核对的请求，不能直接导出为已完成步骤。等待、按键等无需寻找元素的步骤共用原动作语义。

视觉决策仍使用截图。树查询由录制器或回放驱动在绑定目标内执行，脚本保存重找目标所需的条件。录制时的坐标和临时节点句柄只用于当次命中与核对。

## 回放时选择定位模式

| 模式 | 在新画面上如何找到目标 |
| --- | --- |
| 图像识别（`image`） | 用步骤的视觉描述和可选参考图，在当前截图中定位，再按当前观察的坐标映射派发。 |
| 元素树识别（`tree`） | 在当前页面或原生窗口重新查询定位条件，检查目标唯一、可交互且归属正确，再执行动作。 |

回放前检查各步骤是否具备所选模式的定位信息和平台能力，缺失时指出具体步骤。运行中目标缺失或匹配有歧义时，报告步骤、模式和原因；禁止静默切换模式或点击录制时的旧坐标。动作结果未知时沿用现有核对与恢复规则。

两种模式使用相同的结果判定。录制已有 QA 用例时沿用其断言和 probe。自由操作生成的动作序列可以回放，业务通过仍需有明确预期，例如详情页显示订单 A。

## 各平台的元素树

| 设计目标 | 树来源 | 可保存的定位条件 |
| --- | --- | --- |
| Web | 绑定页面的 DOM | 稳定测试标识、业务容器、角色和可访问名称 |
| Android | Appium / UiAutomator2 | `resource-id`、内容描述、所属列表行 |
| iOS | Appium / XCUITest | 应用提供的辅助功能标识、控件类型、标签和所属容器 |
| Windows | UI Automation | 绑定窗口内的 `AutomationId`、控件类型及父容器 |
| macOS | Accessibility（AX） | 绑定窗口内可用的 `AXIdentifier`、角色及容器 |

跨尺寸回放在同一平台重新解析目标。列表排序或控件位置变化时，业务对象仍须匹配；平台间复用同一业务流程需要分别提供对应的定位条件。若窄屏把目标收进“更多”菜单，脚本需有已验证的展开步骤或条件分支。

## 待验收场景

- **跨尺寸与同名元素。** 让 AI 在宽屏录制“打开订单 A 的详情”。缩窄窗口或旋转设备，并交换订单 A、B 的顺序。用同一脚本分别运行两个模式，以实际打开的订单标识验证结果。
- **严格模式。** 录制仅暴露画布的自绘控件，选择树模式时应在派发前指出缺少定位器的步骤。另在回放时移除目标或制造两个同样匹配的目标，检查报告并确认没有误点。
- **响应式操作分支。** 窄屏将“详情”收进菜单时，分别验证宽屏直接点击和窄屏先展开的路径，两条路径都应打开同一订单。

各端分别记录真实设备或窗口上的结果。设计参考 Midscene 录制操作与保存回放目标的做法；Saygo 首版的事件来源限定为自身派发的 AI 动作。[Midscene 录制器](https://github.com/web-infra-dev/midscene/blob/main/packages/recorder/src/recorder.ts) · [Midscene 定位参数](https://v1.midscenejs.com/reference/)
